# 日切放行

> 遵守 `ops/底座生成前必读_效率与技术栈.md`。FastAPI + Vue 3 + SQLite，交付须 docker compose 一键起；库用 SQLite，不挂外置 Postgres。  
> **禁止同构换皮**：本仓主链路、表结构、接口与页面均独立，不得与其它仓共用同一套 `/api/items` 壳。

## 骨架一句话

业务日分区切片登记后裁决完整度，完整才放行下游，并与消费水位对账

## 为何能出多题

迟到切片、重切、跨分区依赖、部分完整冻结、消费水位回拨

## 避开

别做成作业拓扑编排换皮；别做成纯水位大盘

## 互斥切口候选

- 迟到切片整批拒收 vs 进待补齐冻结区
- 重切失败整笔回滚 vs 保留已完整分区
- 放行与水位同步闸 vs 异步放行后纠偏

## 重切闭环（本仓已钉死口径）

互斥命运按正确性固定为 **方案甲：整笔回滚**，并在 `recut_ledger`（重切裁决簿）按业务日钉死：

- 重切任一步失败（未齐、切片号冲突、落库异常）→ 本趟整笔回滚，旧放行态与消费水位保持重切前快照。
- 同业务日同分区分片号冲突必须整次失败闭；已完整但未放行的行也不保留，绝不混用方案乙。
- 禁止新旧两套正式放行并存：重切成功时旧切片整片撤回（`已撤回` / `已归档`），只留一套正式放行。
- 禁止重切中途把水位推到未完整切片：水位只在新切片全量完整且已落库、已放行后推进。
- 口径首次写入裁决簿后当天不得更换；请求偏离（如要求「保留完整」）→ 拒绝并记「重切口径偏了」，不写任何切片或水位。
- 同分区两名值班同时重切 → 加锁互斥排队，后到者记「重切争用」，不静默通过。

对应页面：切片登记、完整度裁决、下游放行、重切队列、分区详情、消费水位、重切裁决簿；队列/详情/水位及策略旁注、列表角标共用同一批口径字段。
